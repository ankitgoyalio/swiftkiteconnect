# Domain docs

## Before exploring

Read root `GLOSSARY.md`, if present, and ADRs in `docs/adr/`
that concern the area being explored.

If these documents are absent, proceed silently. The
domain-modeling skill creates them when terms or decisions
are resolved.

## Layout

This repository uses one domain context:

- `GLOSSARY.md`: shared domain vocabulary.
- `docs/adr/`: architecture decision records.

## Vocabulary and decisions

Use glossary terms when naming domain concepts in issues,
proposals, code, and tests. Note real vocabulary gaps for
domain-modeling.

If a proposal conflicts with an ADR, identify the ADR and
explain why the decision should be reconsidered.
